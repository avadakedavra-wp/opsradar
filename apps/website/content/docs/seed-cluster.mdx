# Demo Cluster

Want something for OpsRadar to find? Plant two Deployments with deliberate problems in a throwaway namespace. This is self-contained — copy and paste, nothing to clone.

## Apply the demo workloads

```bash
kubectl apply -f - <<'EOF'
apiVersion: v1
kind: Namespace
metadata:
  name: ops-radar-demo
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: over-provisioned-app
  namespace: ops-radar-demo
spec:
  replicas: 1
  selector:
    matchLabels: { app: over-provisioned-app }
  template:
    metadata:
      labels: { app: over-provisioned-app }
    spec:
      containers:
        - name: web
          image: nginx:latest          # unpinned tag
          resources:
            requests:
              cpu: "4000m"              # 4 full cores — actual usage is a few millicores
              memory: "2Gi"
          # no livenessProbe / readinessProbe
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: missing-limits-app
  namespace: ops-radar-demo
spec:
  replicas: 1
  selector:
    matchLabels: { app: missing-limits-app }
  template:
    metadata:
      labels: { app: missing-limits-app }
    spec:
      containers:
        - name: web
          image: nginx:1.25
          # no resources block, no probes
EOF
```

## What OpsRadar finds

### `over-provisioned-app`

- CPU massively over-provisioned (4000m requested vs a few millicores actual)
- Unpinned image tag `nginx:latest`
- Missing liveness probe
- Missing readiness probe

### `missing-limits-app`

- No resource requests
- No resource limits
- Missing liveness probe
- Missing readiness probe

## Demo walkthrough

```bash
# 1. Plant the problems (command above), then start OpsRadar
opsradar start                       # or: docker compose -f deploy/docker-compose.yml up

# 2. Open the dashboard  (:6689 for the CLI, :3000 for Docker/dev)
#    Click "Scan Now" — watch findings stream in live

# 3. On a finding, either:
#      • "Generate PR"  — open a fix PR on GitHub
#      • "Apply"        — patch the live cluster now

# 4. Resolve a finding
curl -X POST http://localhost:8080/findings/<id>/resolve

# 5. Scan again — the radar drops the resolved finding
```

## Verify the radar

After a scan, `GET /radar` should show open findings under `ops-radar-demo`, for example:

```json
{
  "radar": [
    { "namespace": "ops-radar-demo", "critical": 2, "high": 3, "medium": 1, "low": 0 }
  ]
}
```

Exact counts depend on your AI backend and model.

## Clean up

kubectl delete namespace ops-radar-demo
